## 特化内容

原版 project-graph 的 `Settings.mouseLeftMode` 已有 `selectAndMove` / `connectAndCut` 两档（ControllerNodeConnection 按
此分发），但**没有快捷键能切换**——桌面端靠 Tauri 窗口事件，左键事件不会被浏览器层拦截。

web 版不同：Edge 等浏览器自带手势层会吞掉画布上的左键事件，用户可能永远拖不出连线。nx-pg 的特化是
**单按 C 键在两档间切换**，并在画布顶部弹 1 秒 HUD 提示当前模式：

- `selectAndMove`（默认）= 创建模式：双击空白建节点、左键拖框选、拖动节点
- `connectAndCut` = 连线/斩断模式：左键拖出连线（ControllerNodeConnection）、划过节点/连线切割删除（ControllerCutting）

本服务**只做「切换 + 提示」，不新增交互语义**——两档的真实语义全部由既有 controller 分发（原版逻辑零复制改动）。
文案与底部工具栏 tooltip 对齐（zh_CN.yml：选中/移动 ↔ 连线/斩断）。

## 关键决策

1. **为什么是裸 keydown 而不是 shortcutKeysRegister**：走注册表会跟已有 `C-c`（复制）等条目冲突，
   且 c 键语义是「模式开关」而非「命令」；裸监听 + 排除修饰键最简单。改键位设置页（KeyBindsSettingsWindow）
   **看不到也不管理这个键**——排查 c 键失效时直接查 Controller.tsx，别去注册表里找。
2. **为什么独立成文件**：Controller 总控用 `import.meta.glob("./concrete/*.tsx")` 扫描并按「第一个名字含
   Class 的导出」实例化子控制器。塞在 ControllerEntityCreate 同文件里虽然不匹配 Class，但导出表易被误改——拆开更稳
   （曾因此坏过双击建节点，commit a6a1fbd）。
3. **防抖 50ms 的原因**：Canvas.tsx 把 window keydown 重定向派发到 canvas 元素；合成事件（自动化测试造的
   `bubbles:true`）会两条路径各触发一次 → 连切两下 = 净零。真实键盘不受影响，防抖只护测试场景。
4. **HUD 不用 toast/DOM**：画布内容用 canvas 2D 直绘（renderer 钩子），与缩放/平移无耦合，也不被 UI 层遮挡。
