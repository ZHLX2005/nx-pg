# nx-pg 特化处理 diff-log

## 项目背景（一句话定位）

**project-graph**（`.claude/repo/project-graph/`，只读）是原版 Tauri2 桌面项目；**nx-pg** 是目的项目——Node 全栈 web 版，运行在浏览器。迁移目标见仓库根 `Agent.md`：只复刻核心画布编排能力，排除 AI/扩展/涂鸦/生态，设计原则是**够用就行**。

因此 nx-pg 的代码分两类：

| 类别 | 判定 | 处理原则 |
| --- | --- | --- |
| **迁移件** | 与原版一致（可字节级复制的部分） | 不登记 diff；坏了对照原版修 |
| **特化件** | 相对原版有意识改动（web 兜底 / 新增交互 / 删减入口） | **必须在本 skill 的 references/ 登记** |

登记 diff 的目的：迁移项目的最大风险是「改动半年后没人记得这是故意的还是 bug」。本 skill 就是那个"故意的"名单——分析代码时先查这里，避免把特化当回归"修复"掉。

## 何时读本 skill

- **动手前**：给 nx-pg 加与原版不同的新行为 → 先读对应 ref，了解既有特化的模式与位置约定
- **分析时**：发现 nx-pg 与原版不一致 → 先查这里区分「有意特化 / 需修复的回归」
- **收尾时**：新特化落地后（含 headless 验证）→ 按下述格式登记新 ref

## 特化登记约定

每个特化一个 ref，按 A 序列编号（A = 项目特化序列，与 key_board 的 X/Y/Z 序列不撞名）：

```
references/A<NN>-<主题>.md
```

ref 结构约定（保持简洁，特化不是教程）：

```markdown
---
name: A<NN>-<主题>
description: 一句话——特化了什么 + 触发词（供路由检索）
---

## 特化内容（一段话：原版是什么 / nx-pg 改成什么 / 为什么 web 需要）
## 实现位置（文件路径:行号 级别的锚点清单）
## 关键决策（为什么不按原版做；踩过的坑一句话带过）
```

**编号规则**：顺序分配，不复用已废弃编号（废弃 ref 加 `> 已废弃（原因）` 头注释保留）。

## 登记新特化的检查清单

- [ ] 确认这不是纯迁移件（与原版对照过，确实不同）
- [ ] 确认特化已实现并验证（headless 实测或 pnpm run test 全绿）
- [ ] ref 含：特化内容 / 实现位置锚点 / 关键决策三节
- [ ] 路由表已登记该 ref 的「何时读取」
- [ ] `PROGRESS.md` 轮记录已有对应条目（skill 记"是什么为什么"，PROGRESS 记"哪轮做的"）

## 错误案例

| 错误操作 | 实际后果 | 正确做法 |
| --- | --- | --- |
| 把与原版一致的迁移件登记成 diff | diff 名单膨胀，噪声淹没真特化 | 先对照原版，一致的不登记 |
| 只写"改了 X"不写"原版是什么、为什么改" | 半年后无法判断是特化还是回归 | 三节结构缺一不可 |
| 特化改动顺手扩散到未登记文件 | diff 记录与实际代码漂移 | 每次改完对照 ref 里的锚点清单核实 |
